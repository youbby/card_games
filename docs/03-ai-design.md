# 03. CPU AI 설계 (클래스 Low / High)

## 1. 공통 구조

```ts
interface PokerBot {
  decide(view: BotView): Promise<Action>;  // view: 자기 홀카드 + 공개 정보만
}
```

- AI는 **엔진이 만든 읽기 전용 뷰**만 받는다 (상대 홀카드나 남은 덱에 접근 불가 → 치팅이 구조적으로 불가능)
- 반환한 액션은 엔진이 `legalActions`로 검증, 불법이면 가장 가까운 합법 액션으로 보정
- 생각 시간 연출: 0.6~2.0초 랜덤 (어려운 결정일수록 길게, 설정에서 단축 가능)
- 클래스가 **판단 알고리즘**을 정하고, 캐릭터별 **성향**이 그 안에서 개성을 만든다

```ts
interface Personality {
  tightness: number;   // 0..1, 높을수록 참여하는 핸드가 적음
  aggression: number;  // 0..1, 높을수록 베팅/레이즈 선호
  bluff: number;       // 0..1, 블러핑 빈도
}
```

- 성향은 CPU 생성 시 클래스별 범위 안에서 랜덤으로 정해져 **저장** → 같은 CPU는 항상 같은 스타일
- 로비의 CPU 목록에서 성향을 아이콘으로 표시 (예: 🪨 타이트, 🔥 공격적)
- CPU 바이인 금액·리바이 여부도 성향에 따라 결정 (공격적일수록 크게 앉고 리바이 잦음)

## 2. Low 클래스 — "실수하는 초보"

목표: 기본만 지켜도 이길 수 있는 상대. 너무 바보 같으면 재미없으므로 가끔 강하게 나온다.

- **프리플랍**: 핸드 점수(Chen 공식) 임계값이 낮음 → 약 45~60% 핸드 참여. 레이즈는 프리미엄(AA~QQ, AK)에서만, 나머지는 림프/콜
- **포스트플랍**: 지금 완성된 족보만 봄 (드로우·보드 텍스처 무시)
  - 원페어 이상 → 대체로 콜, 투페어 이상 → 가끔 베팅
  - 아무것도 없으면 체크, 베팅을 받으면 일정 확률로 콜 (콜링 스테이션 성향)
- **베팅 크기**: 고정 (2~3BB 또는 팟의 ⅓)
- **포지션·상대 성향 무시**
- **실수 넣기**: 약 10% 확률로 무작위 합법 액션
- 큰 올인에는 대체로 폴드 (강한 핸드 제외)

## 3. High 클래스 — "생각하는 상대"

목표: 기본기 있는 플레이어도 방심하면 지는 수준. 완벽한 GTO가 아니라 **합리적이고 상대 약점을 파고드는** 봇.

### 3.1 프리플랍
- 169개 시작 핸드 순위표 + **포지션별 오픈 레인지** (UTG 타이트 ~ BTN 루즈), 인원수에 따라 레인지 조정
- 오픈 레이즈 2.5~3BB (+림퍼당 1BB)
- 3벳: 프리미엄 + 일부 블러프 3벳(A5s 등)
- 레이즈에 대한 콜/폴드: 레인지와 남은 스택 대비 가격으로 결정

### 3.2 포스트플랍 — 승률(에퀴티) 기반
1. **몬테카를로 승률 계산**: 남은 카드를 무작위로 깔아 300~1,000회 시뮬레이션 → 승률(무승부 가중)
   - 상대 레인지 좁히기(선택): 프리플랍에 레이즈한 상대는 상위 핸드에서만 샘플링
   - 계산은 **Web Worker**에서 → UI 끊김 방지
2. **팟 오즈** 비교: `필요 승률 = 콜 금액 / (팟 + 콜 금액)`
3. 결정 테이블 (대략):
   | 승률 | 앞에 베팅 없음 | 베팅 받음 |
   |---|---|---|
   | 매우 높음 (≥ 75%) | 밸류 베팅 ½~¾팟, 가끔 슬로우플레이 | 레이즈 |
   | 높음 | 베팅 | 콜 또는 레이즈 |
   | 팟 오즈 이상 | 체크 / 가끔 베팅 | 콜 |
   | 드로우(플러시·양방향 스트레이트) | 세미블러프 베팅 | 임플라이드 오즈 고려해 콜 |
   | 낮음 | 체크, `bluff` 확률로 블러프 | 폴드 |
4. **컨티뉴에이션 벳**: 프리플랍 레이저가 마른 보드에서 높은 빈도로 c-bet
5. **베팅 크기 다양화**: ⅓ / ½ / ¾ / 팟 / 오버벳, 노이즈를 섞어 패턴 노출 방지

### 3.3 플레이어 성향 파악
세션 중 플레이어의 VPIP, PFR, 공격성, c-bet 폴드율을 추적해 조정:
- 플레이어가 콜을 많이 함 → 블러프 줄이고 밸류 베팅 크게
- 플레이어가 폴드를 많이 함 → 블러프·스틸 늘림
- 플레이어가 공격적 → 강한 핸드로 체크-레이즈/트랩 증가

MVP는 세션 단위. 이후 플레이어 캐릭터의 장기 전적을 쓰는 것도 가능.

### 3.4 스택 깊이
- 숏스택(≤ 15BB): 푸시/폴드 차트
- 그 외: 위 로직

## 4. 검증 방법 (헤드리스 시뮬레이터)

UI 없이 엔진 + 봇만 돌리는 스크립트로 대량 대전:

| 대전 | 기대 결과 |
|---|---|
| High vs Low (헤즈업, 10만 핸드) | High가 확실한 흑자 (예: +10BB/100핸드 이상) |
| High vs 랜덤 봇 | 큰 흑자 |
| Low vs 랜덤 봇 | 흑자 |
| 모든 봇 | 불법 액션 0건, 칩 총량 보존 |

같은 시뮬레이터로 엔진 버그(칩 증발, 무한 루프)도 잡는다.

## 5. CPU 풀 경제 균형
CPU끼리는 플레이어 없이 대전하지 않으므로, CPU 칩은 **플레이어와 같은 테이블에 앉았을 때만** 변한다.
- Low CPU는 플레이어에게 칩을 잃는 경향 → 파산·교체가 잦음 (의도된 동작)
- High CPU는 칩이 쌓이는 경향 → 높은 블라인드 단계에서도 상대 확보 가능
- 시뮬레이터로 "플레이어 평균 실력" 가정 시 클래스별 CPU 교체 주기를 확인하고 필요하면 바이인 성향 조정
