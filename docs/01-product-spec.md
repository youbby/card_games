# 01. 제품 명세

## 1. 범위

### MVP (1차 출시)
- 캐릭터 생성/선택, 캐릭터별 칩 잔액
- CPU 풀 (Low 10 / High 10) 자동 유지
- 게임 시작 흐름: 게임 → 클래스 → 인원 → 블라인드·바이인 → 시작
- 텍사스 홀덤 노리밋 캐시 게임 (2~6인)
- 파산 판정 및 캐릭터 잠금
- 캐릭터별 전적 (통계 + 세션 + 최근 핸드)
- 설정: 시작 칩, 사운드/진동, 애니메이션 속도, 전체 초기화
- 완전 오프라인 동작

### MVP 이후 (후보)
- 다른 게임 추가 (오마하, 블랙잭, 세븐 포커 등) — 구조는 처음부터 대비
- 토너먼트(Sit & Go)
- CPU 명예의 전당 (파산해 삭제된 CPU 기록)
- 앱 안에서 새 버전 확인 (GitHub Releases API)

### 하지 않는 것
- 온라인 멀티플레이, 서버, 로그인
- 현금 결제, 칩 구매, 실제 돈과의 연결 — **도박 목적이 아님**

    │  ├─ + 새 캐릭터
    │  └─ 파산 캐릭터 (회색, 전적만 열람)
    ▼
[로비]
    │  ├─ 내 캐릭터 카드 (잔액, 간단 전적) → [전적 상세]
    │  ├─ 게임 목록 (현재: 텍사스 홀덤)
    │  ├─ CPU 목록 보기 (Low/High 각 10명, 잔액·전적)
    │  ├─ 캐릭터 변경
    │  └─ 설정 (시작 칩, 사운드, 전체 초기화…)
    ▼
[게임 설정]  ① 클래스 → ② 인원 → ③ 블라인드 → ④ 바이인 → ⑤ 상대 확인
    │
    ▼
[테이블]
    │  ├─ 일어나기 → 칩 정산 → 로비
    │  └─ 스택 0 → 리바이 / 일어나기 → (잔액 부족이면) [파산 안내]

## 3. 플레이어 캐릭터

| 항목 | 내용 |
|---|---|
| 식별 | 기기 내 UUID. 이름은 표시용 (활성 캐릭터끼리 중복 불가, CPU 이름과도 중복 불가) |
| 생성 정보 | 이름, 아바타 |
| 시작 칩 | 설정의 **시작 칩** 값 (기본 10,000). **캐릭터를 생성하는 순간에만 적용**되며, 이후 설정을 바꿔도 기존 캐릭터 잔액은 변하지 않음 |
| 개수 | 여러 개 허용 |
| 상태 | `ACTIVE` / `BANKRUPT` (한 번 파산하면 되돌릴 수 없음) |
| 삭제 | 활성·파산 캐릭터 모두 확인 후 개별 삭제 가능 |

### 실행 시 캐릭터 선택
- 앱을 켤 때마다 캐릭터 선택 화면부터 시작 (마지막 캐릭터 강조)
- 활성 캐릭터가 0명이면:
  - 캐릭터가 하나도 없음 → 바로 **캐릭터 생성**
  - 모두 파산 → "모든 캐릭터가 파산했습니다. 새 캐릭터로 다시 시작하세요" 안내 + 생성 버튼 + 지난 전적 보기

### 파산
- **조건**: 테이블에 앉아 있지 않고 `잔액 < 가장 낮은 블라인드 단계의 최소 바이인` (기본값 기준 400)
- **판정 시점**: 테이블에서 일어날 때, 테이블 스택이 0이 되어 리바이 못 할 때, 앱 시작 시
- 파산 → `BANKRUPT`로 영구 변경, 플레이 불가, 전적은 열람 가능
- 리필/보너스 없음 → 새 캐릭터 생성

## 4. CPU 풀

CPU도 플레이어처럼 **칩을 가진 영속 캐릭터**입니다.

| 항목 | 내용 |
|---|---|
| 구성 | **Low 10명 + High 10명** (최초 실행·전체 초기화 시 생성) |
| 시작 칩 | **클래스별 고정값**: Low 10,000 / High 50,000 (설정의 시작 칩과 무관). High는 VIP 단계(최소 바이인 20,000)에도 앉을 수 있어야 하므로 더 많이 시작 |
| 성향 | 캐릭터마다 tightness / aggression / bluff 값 (03-ai-design.md), 생성 시 랜덤으로 정해져 저장 |
| 이름·아바타 | 이름 목록에서 겹치지 않게 생성 |
| 칩 | 게임 결과에 따라 늘거나 줄며 영구 저장 |
| 전적 | 핸드 수, 승리 수, 손익 (간단하게) |

### 파산과 보충
- CPU 파산은 두 시점에서 판정
  - **게임 중**: 테이블 스택이 0이 됐을 때 지갑도 0이면 즉시 파산. 지갑에 칩이 남아 있으면 그 칩으로 리바이(최소 바이인 미만이어도 허용)해서 계속 플레이
  - **게임 종료 후**(정산 직후): 잔액이 **자기 클래스에서 가장 낮은 블라인드 단계의 최소 바이인**보다 적으면 파산 (Low: 400 / High: 2,000)
  - 플레이어는 어느 클래스든 고를 수 있으므로 전체 최저값(400) 기준, CPU는 자기 클래스 테이블에만 앉으므로 클래스 기준
- 파산한 CPU는 **삭제**되고, 같은 클래스에 **새 CPU를 즉시 생성** → 클래스별 활성 CPU 항상 10명 유지
- 보충 시점: 세션 종료 시, 핸드 중 CPU가 파산해 자리를 떠날 때, 앱 시작 시 (풀 무결성 검사)
- 플레이어의 핸드 기록에는 상대 이름이 **스냅샷으로 저장**되므로 CPU가 삭제돼도 기록은 남음

## 5. 게임 시작 흐름 (로비 → 테이블)

| 단계 | 선택 | 규칙 |
|---|---|---|
| ① 게임 | 텍사스 홀덤 | 이후 게임 추가 시 목록에 표시 |
| ② 클래스 | **Low / High** | 한 테이블의 CPU는 모두 같은 클래스 |
| ③ 인원 | **2 ~ 6명** (나 포함) | 참가 가능한 CPU가 부족하면 해당 인원 비활성 + 사유 표시 |
| ④ 블라인드 | 아래 표에서 **선택한 클래스에 허용된 단계만** | 내 잔액이 최소 바이인 미만인 단계는 잠김 (자물쇠 + "최소 X칩 필요") |
| ⑤ 바이인 | 최소 20BB ~ 최대 100BB (내 잔액 한도) | 슬라이더 + 최소/중간/최대 버튼 |
| ⑥ 상대 확인 | 자동 선발된 CPU 목록 (이름·성향 아이콘·잔액) | "다시 뽑기" 가능 → **게임 시작** |

### 블라인드 단계와 클래스별 허용 범위

| 등급 | 블라인드 | 바이인 범위 | 하수 | 고수 |
|---|---|---|:---:|:---:|
| 입문 | 10 / 20 | 400 ~ 2,000 | ✅ | — |
| 일반 | 25 / 50 | 1,000 ~ 5,000 | ✅ | — |
| 중급 | 50 / 100 | 2,000 ~ 10,000 | — | ✅ |
| 고급 | 100 / 200 | 4,000 ~ 20,000 | — | ✅ |
| VIP | 500 / 1,000 | 20,000 ~ 100,000 | — | ✅ |

- **하수(Low)**는 입문·일반만 선택 가능 (중급 선택 불가)
- **고수(High)**는 중급·고급·VIP만 선택 가능 (입문·일반 없음)
- 하수에서 칩을 모아 최소 2,000칩을 확보하면 고수의 중급 테이블에 도전 가능
- 선택 가능 = **클래스 허용** AND **내 잔액 ≥ 최소 바이인** AND **참가 가능한 CPU가 있음**

예) 잔액 3,000으로 High 선택 → 중급만 선택 가능 (고급 4,000·VIP 20,000은 잠김)

### CPU 선발
- 대상: 선택한 클래스의 활성 CPU 중 **잔액 ≥ 선택한 단계의 최소 바이인**
- 그중 무작위로 (인원 − 1)명 선발
- CPU 바이인: 성향에 따라 최소~최대 바이인 사이에서 결정 (자기 잔액 한도)
- 높은 단계에서 CPU 잔액이 부족하면 가능한 인원이 줄어듦 → ③에서 미리 표시

### 테이블 진행 중 CPU 처리
- CPU 스택 0 → 지갑에 칩이 있으면 리바이 (`min(지갑, 희망 바이인)`), 지갑도 0이면 **파산 → 삭제 + 클래스 보충**
- 빈자리는 같은 클래스 대기 CPU로 채워 **선택한 인원 유지** (가능한 CPU가 없으면 인원이 줄어든 채 진행)
- 플레이어가 일어나면 남은 CPU는 모두 스택을 정산(캐시아웃)

## 6. 테이블 화면
- 최대 6석 (세로 화면, 나는 하단 고정), 인원에 따라 배치 자동 조정
- 딜러 버튼, SB/BB 표시, 좌석별 이름·클래스 색·스택·현재 베팅·액션
- 액션 바: Fold / Check / Call / Bet·Raise(슬라이더 + ½팟·¾팟·팟 프리셋) / All-in
- 내 현재 족보, 팟·사이드팟, 쇼다운 시 이긴 5장 강조
- 핸드 로그 (접기/펼치기)
- 메뉴: 일어나기, 리바이, 설정

## 7. 전적

### 플레이어 캐릭터 통계 (영구 누적)
- 핸드 수, 이긴 핸드 수, 승률
- 누적 손익, 최고 잔액, 최대 획득 팟, 최대 단일 핸드 손실
- 최고 족보와 달성 일시
- 쇼다운 진출률 / 쇼다운 승률
- VPIP, PFR
- 클래스별(Low/High)·블라인드 단계별·인원별 손익
- 세션 수, 총 플레이 시간

### 세션 기록
게임 시작~일어나기 1회. 클래스, 인원, 블라인드, 바이인, 캐시아웃, 손익, 핸드 수, 시간, 상대 목록.

### 핸드 히스토리
캐릭터당 최근 500핸드: 홀카드, 보드, 포지션, 액션 요약, 팟, 결과, 상대 이름 스냅샷. 통계는 따로 누적하므로 오래된 핸드가 지워져도 통계는 유지됩니다.

## 8. 설정

| 항목 | 내용 |
|---|---|
| 시작 칩 | 1,000 / 5,000 / **10,000** / 50,000 / 100,000 / 직접 입력 (1,000 ~ 1,000,000). **플레이어 캐릭터를 생성할 때만 적용**. 기존 캐릭터 잔액과 CPU에는 영향 없음 |
| 사운드 / 진동 | 켜기·끄기 |
| 애니메이션 속도 | 느림 / 보통 / 빠름 |
| CPU 생각 시간 | 짧게 / 보통 |
| **전체 초기화** | 아래 참고 |
| 앱 정보 | 버전, GitHub 릴리스 페이지 링크 |

> 시작 칩 최솟값(1,000)은 가장 낮은 단계의 최소 바이인(400)보다 커야 합니다. 그래야 새 캐릭터가 생성 즉시 파산하지 않습니다.

### 전체 초기화
앱을 **설치 직후 상태로 되돌리는 기능**.
- 삭제 대상: 모든 플레이어 캐릭터, 모든 CPU, 모든 전적·세션·핸드 기록, **설정(기본값으로 복원)**
- 2단계 확인: 경고 화면 → "초기화" 입력 후 확정
- 실행 후: 설정 기본값 복원 → CPU 풀(Low 10 / High 10) 새로 생성 → 첫 실행처럼 캐릭터 생성 화면으로
