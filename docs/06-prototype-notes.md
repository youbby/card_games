# 06. 프로토타입 참고 메모 — `texas_hold_em_poker.html`

기존 프로토타입은 **"이런 느낌의 게임"을 보여주는 참고 자료**이며, 코드는 재사용하지 않고 새로 작성한다.
파일은 프로젝트 루트에 그대로 두고 앱 빌드에는 포함하지 않는다.

## 1. 참고할 점 (느낌·방향)
- 화면 구성: 상단 헤더 / 가운데 펠트 테이블 / 하단 고정 로그 + 액션 바
- 테이블 분위기: 초록 펠트 그라데이션, 나무 테두리, 흰 카드 앞면 + 파란 사선 뒷면, 현재 차례 좌석의 금색 테두리
- 액션 바: Fold(빨강) / Check(회색) / Call(파랑, 금액 표시) / Raise(초록, 슬라이더) / All-in(보라)
- 내 족보를 카드 위에 작은 배지로 표시
- 세로 모바일 화면 기준, 하단 제스처바 safe-area 대응

## 2. 새로 만들 때 피해야 할 함정 (프로토타입에서 발견된 문제)

| 문제 | 새 설계에서의 대응 |
|---|---|
| 사이드팟 없음 — 승자가 팟 전체를 가져감 | 02-holdem-rules §4 사이드팟 알고리즘 |
| 무승부 분배 시 나머지 칩 증발 | odd chip 규칙 + 칩 총량 불변식 테스트 |
| 최소 레이즈 규칙이 실제와 다름 | 직전 증가분 기준 (02 §3) |
| AI가 최소 레이즈 미만으로 레이즈 가능 | 엔진이 모든 액션을 `legalActions`로 검증 |
| 헤즈업 블라인드·액션 순서 규칙 없음 | 02 §2 |
| 불완전 올인이 베팅을 다시 엶 | 02 §3 |
| 칩 0이면 자동 리필 | 파산 규칙으로 대체 (리필 없음) |
| 리셋 시 AI 타이머가 취소되지 않아 상태 꼬임 | 엔진은 순수 함수, 타이머는 세션 컨트롤러가 관리·취소 |
| 1명만 칩이 남아도 매 스트리트 액션 요구 | 런아웃 자동 처리 |
| 콜 금액이 스택보다 크면 Call 불가 | Call = 올인 콜 |
| 좌석 3개 고정, DOM id 하드코딩 | 2~6인 가변 좌석 컴포넌트 |
| 게임 로직과 DOM 조작이 섞여 있음 | 엔진/UI 분리 (04-architecture) |
| 로그를 `innerHTML`로 출력 | 캐릭터 이름 입력이 생기므로 텍스트로만 렌더링 |
| Tailwind·아이콘을 CDN `@latest`로 로드 | 번들에 포함, 버전 고정 |
